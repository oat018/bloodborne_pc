## Findings

1. **[P2] Forced lavapipe can silently run on hardware** — `tests/gpu_tests.sh:32-35`.
   With `BB_TEST_LAVAPIPE=1`, failure to obtain lavapipe leaves the previously detected hardware device selected. The script runs Vulkan tests on that device and can print PASS, contrary to the documented forced-backend contract. Fail explicitly or clear the device and report the software-driver prerequisite as SKIP; do not retain hardware in forced mode. Add a regression with hardware available and Nix/lavapipe unavailable.

2. **[P2] A NUL-prefixed settings line calls back() on an empty string** — `gpu/shim/bbport_settings.cpp:27-29`.
   `fgets` succeeds for bytes NUL/newline, but `line += chunk` appends nothing because it treats the chunk as a C string. `line.back()` then has undefined behavior. The old reader safely ignored this malformed input. Guard against an empty accumulated line before calling back(), and add a corrupt-settings regression. Without the fix a damaged `BB_CONFIG` file can abort a hardened build or cause undefined behavior in production.
