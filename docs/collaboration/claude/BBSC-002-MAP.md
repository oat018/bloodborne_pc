## 1. What a complete 0.0.2 BBport client is

The 1.7.2 network patch alone is not BBSC. It changes transport only. Its own header comment says the gameplay callbacks are no-ops because "BBSC frames ... are handled by the BBSC mod DLL through the relay and its own P2P channel" ([B patch L4763-4776](https://github.com/CLSAMG22/BBSC/blob/4f11faf88b6ba658ebde6fe5fbefdadedba4fa41/bbport/bbport-1.7.2-bbsc.patch#L4763-L4776)). Unpatched 1.7.2 has the same header shape with no seamless code at all: "Seamless co-op (host placement) is not ported yet" ([S gpu/shim/core/bloodborne_re.h L1-3](https://github.com/Supermedo/bloodborne_pc/blob/e5d04e2ba4864ccf40de6c3cf6aa532855320b0d/gpu/shim/core/bloodborne_re.h#L1-L3)).

### Actual load path (Z `tools/play-bbport.ps1`, read in full)

1. It reads `tools/account.dat` (server, name, DPAPI-protected password) and writes `<BBport>\user\host_overrides.custom.json` with three entries:
   - `ss4...:20443` → `http://<server>:20443`
   - the summon URLs → `http://<server>:31315`
2. It sets these environment variables:
   - `BB_PROBE=<pkg>\bbsc\bbsc-launch.exe`
   - `BBSC_EMULATOR=<pkg>\emulator\bb-probe.exe`
   - `BB_ONLINE=1`, `BB_SHADNET_SERVER`, `BB_SHADNET_WEBAPI`, `BB_COMMUNITY_SERVER`, `BB_SHADNET_NPID`, `BB_SHADNET_PASSWORD`, `BB_GAME_DIR`
3. It starts BBport's `Bloodborne.exe --run` with the BBport folder as the working directory. The `-Launcher` mode instead edits `%APPDATA%\bbport-launcher\settings.json`, because that Online page overrides the environment (it keeps a `.bak` first).
4. BBport `run.py` then takes over:
   - it uses `BB_PROBE` as the game executable ([S run.py L270](https://github.com/Supermedo/bloodborne_pc/blob/e5d04e2ba4864ccf40de6c3cf6aa532855320b0d/run.py#L270))
   - it changes to the port folder
   - it uses the custom overrides file as-is and exports `SHADPS4_HTTP_HOST_OVERRIDES_JSON` ([S run.py L46-70](https://github.com/Supermedo/bloodborne_pc/blob/e5d04e2ba4864ccf40de6c3cf6aa532855320b0d/run.py#L46-L70))
5. Inside the game:
   - The DLL waits for the eboot at `0x800000000`.
   - It checks every byte-patch site before writing any of them, and changes nothing if one site differs ([B bbsc_mod.cpp L4-19, L380-455](https://github.com/CLSAMG22/BBSC/blob/4f11faf88b6ba658ebde6fe5fbefdadedba4fa41/emulator/mod/bbsc_mod.cpp#L380-L455)).
   - It swaps the game's libSceHttp import slots for its own wrappers ([B bbsc_http.cpp L1-34](https://github.com/CLSAMG22/BBSC/blob/4f11faf88b6ba658ebde6fe5fbefdadedba4fa41/emulator/mod/bbsc_http.cpp#L1-L34)).
   - It reads the overrides file from `SHADPS4_HTTP_HOST_OVERRIDES_JSON` first ([B bbsc_http.cpp L679-701](https://github.com/CLSAMG22/BBSC/blob/4f11faf88b6ba658ebde6fe5fbefdadedba4fa41/emulator/mod/bbsc_http.cpp#L679-L701)).
   - It opens the TCP relay at the game-server host on port 20444 ([B bbsc_relay.cpp L4-16](https://github.com/CLSAMG22/BBSC/blob/4f11faf88b6ba658ebde6fe5fbefdadedba4fa41/emulator/mod/bbsc_relay.cpp#L4-L16)).

So **R02 needs no new loader**. Reproducing R02 means setting the `BB_PROBE`/`BBSC_EMULATOR` pair (or `play-bbport.ps1`) around a 1.7.2+patch `bb-probe.exe` and the 0.0.2 `bbsc.dll`.
